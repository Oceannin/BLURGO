# BlurGo 0.1.0 — draft release notes

BlurGo 0.1.0 is the first public alpha candidate of the native GPU blur filter for OBS Studio.

## Highlights

- Gaussian blur with configurable radius and one to four GPU pass pairs.
- Box blur for a flatter, more uniform result.
- Pixelate mode with configurable block size.
- Effect mix from 0% to 100%.
- Standard OBS source-filter workflow for individual sources and nested/wrapper scenes.
- English and Russian localization.
- Safe bypass on invalid dimensions, missing targets, invisible settings, or GPU render failures.

## Compatibility

- Minimum OBS Studio version: 31.1.1.
- Windows x64: runtime-tested on OBS 31.1.1 and 32.2.2 with Direct3D 11.
- Ubuntu 24.04 x86_64: packaged Debian plugin runtime-tested on OBS 32.2.0 with OpenGL under Xvfb.
- macOS Universal: packaged-plugin runtime-tested natively on Apple Silicon macOS 15.7.7 with OBS 32.2.1 and OpenGL.

## Assets

The tagged release workflow produces:

- Windows x64 portable ZIP.
- macOS Universal archive/package when signing configuration is available.
- Ubuntu 24.04 x86_64 archive and Debian package.
- Ubuntu debug-symbol package.
- Source archive.
- `CHECKSUMS.txt` with SHA-256 hashes.

## Installation

1. Close OBS Studio.
2. Download the package matching the operating system and architecture.
3. Extract the portable layout into the OBS installation, preserving the `obs-plugins` and `data/obs-plugins` directories.
4. Start OBS and confirm the log contains `[blurgo] loaded successfully`.
5. Add **BlurGo** under **Effect Filters** for a source or nested scene.

## Upgrade and rollback

Version 0.1.0 introduces no settings migration. To roll back, close OBS and remove the BlurGo binary plus its `data/obs-plugins/blurgo` directory, then restore the previous plugin package if one exists. Scene collections retain unknown filter settings, so keep a tested scene collection backup before changing plugin versions.

## Known limitations

- The first alpha does not include region masks or animated transitions.
- Windows binaries are not code-signed yet; macOS signing/notarization depends on maintainer certificates.
- Hosted macOS runtime evidence uses Apple Software Renderer and is functional coverage, not a physical-Mac GPU benchmark.
- Game-capture behavior can depend on the game, anti-cheat, capture backend, and GPU configuration. Representative real-game and forced GPU-loss checks are optional post-alpha qualification, not 0.1.0 release blockers.
