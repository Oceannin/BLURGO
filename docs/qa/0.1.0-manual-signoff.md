## Representative real-game capture

Choose a game that the tester is authorized to capture. Do not bypass anti-cheat, DRM, or protected-content controls.

- [ ] Back up the scene collection and open OBS Stats and the current log.
- [ ] Add a Game Capture source using the normal supported capture path for the title.
- [ ] Confirm an unfiltered 60-second baseline has no black frame or capture-hook warning.
- [ ] Apply Gaussian radius 12 / two passes for 60 seconds and record average render time and skipped frames.
- [ ] Exercise Box and Pixelate for at least 30 seconds each.
- [ ] Change radius, passes, block size, and mix live; verify mix 0% is a visual passthrough.
- [ ] Put the Game Capture source in a nested scene and apply BlurGo to that scene source.
- [ ] Alt-tab, switch scenes 20 times, resize or change the game between windowed and borderless where supported, then remove/re-add the filter.
- [ ] Confirm the game, OBS, and capture hook remain stable and the OBS log contains no BlurGo warning/error.

## GPU loss or graphics reinitialization

This gate requires an approved lab method on a disposable machine or VM. The tester owns the method and must be able to recover the system independently. BlurGo does not require or recommend a specific driver-reset mechanism.

- [ ] Start with a saved disposable scene containing active source and nested-scene BlurGo filters.
- [ ] Begin a local recording or preview and record the baseline OBS Stats values.
- [ ] Trigger the approved GPU-device loss or graphics reinitialization.
- [ ] Confirm OBS either recovers rendering with BlurGo active or safely bypasses the filter without crashing.
- [ ] Confirm the preview is not permanently black, filter controls still respond, and re-adding BlurGo restores the effect if OBS discarded graphics state.
- [ ] Restart OBS and confirm the saved filter settings remain intact.
- [ ] Inspect the complete OBS/crash log for BlurGo errors, access violations, repeated allocation failures, or a shutdown leak.
