# BlurGo 0.1.0 Windows smoke test

## Environment

- OBS Studio 31.1.1, 64-bit portable build.
- Windows 11 24H2, build 26100.
- NVIDIA GeForce RTX 4070 Ti SUPER.
- NVIDIA driver 32.0.16.1656.
- OBS D3D11 backend, Rec. 709 Partial SDR output.
- 1920x1080 base canvas and 1280x720 output at 30 fps.

## Automated build evidence

- Clang-format and CMake formatting checks passed.
- Windows x64 build, settings tests, package, and artifact upload passed.
- macOS Universal build, settings tests, package, and artifact upload passed.
- Ubuntu 24.04 x86_64 build, settings tests, package, source tarball, debug-symbol package, and artifact upload passed.

## Runtime evidence

- OBS loaded `blurgo.dll` and reported BlurGo 0.1.0 without a plugin, effect, or shader error.
- OBS WebSocket created the `blurgo_filter` on an image source with all expected settings.
- Gaussian, Box, and Pixelate each produced a non-empty render materially different from the source image.
- Visual inspection confirmed smooth Gaussian blur, uniform Box blur, and hard-edged Pixelate blocks without black frames or obvious edge corruption.
- The same filter attached to the scene source rendered the complete composite and produced a materially different output.

Measured mean absolute RGB difference from the unfiltered 1280x720 test pattern:

| Render | Difference |
| --- | ---: |
| Gaussian, radius 18, 3 passes | 72.9572 |
| Box, radius 18, 3 passes | 90.5343 |
| Pixelate, block size 24 | 3.0904 |
| Scene Gaussian, radius 12, 2 passes | 21.2434 |

## Remaining release gates

- Game, window, and display-capture inputs.
- Live UI control updates, persistence after restart, and filter reordering/removal.
- Transparent edges and extended/HDR color spaces.
- Resize, scene-switch, shutdown, and GPU-reinitialization recovery.
- 1080p60, 1440p60, and 4K60 performance plus a 30-minute memory-stability run.
