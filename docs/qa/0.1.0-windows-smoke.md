# BlurGo 0.1.0 Windows runtime QA

Date: 2026-09-01  
Tested package commit: `75a93cf0690b1a774ea53434026fb96f7e981052`  
Tested DLL SHA-256: `bafa2cdcaf9c07bc88f58705b7c983813a2d9b5b1d385e9651735a30222c1113`  
CI run: [GitHub Actions 33499795348](https://github.com/Oceannin/blurgo/actions/runs/33499795348)

The DLL from this green commit is byte-identical to the binary used for the extended runtime runs. Evidence was produced with `tools/obs-smoke.py` against disposable portable OBS profiles; generated test-pattern screenshots were inspected locally and are not committed.

## Environment

- Windows 11 24H2, build 26100.
- NVIDIA GeForce RTX 4070 Ti SUPER, driver 32.0.16.1656.
- OBS Studio 31.1.1 and 32.2.2, 64-bit portable builds.
- Direct3D 11 graphics backend.
- SDR: NV12, Rec. 709, Partial range.
- HDR: P010, Rec. 2100 PQ, Partial range.

## Functional results

- OBS 31.1.1 and 32.2.2 loaded `blurgo.dll` and logged `[blurgo] loaded successfully (version 0.1.0)` without BlurGo shader/effect errors.
- Gaussian, Box, and Pixelate produced non-empty, materially changed output on an image source.
- A BlurGo filter on a nested scene processed the complete composite.
- Radius, pass count, pixel size, mode, and mix changes applied live through the OBS WebSocket API.
- Mix 0% and blur radius 0 produced pixel-identical passthrough output.
- Settings persisted after restarting both tested OBS versions.
- Transparent source borders remained transparent; visual inspection found no black frames or obvious edge corruption.
- Source resize and deletion, disposable-source deletion, filter reorder/removal, 20-40 scene switches, and OBS restart/shutdown completed without a BlurGo crash.
- A 1080p60 P010/Rec. 2100 PQ run rendered all modes on the source and nested scene. The OBS log confirmed the HDR profile, and the locally inspected test image was neither black nor washed out.

The display-capture harness selected the first available `monitor_id`, made its isolated QA scene visible, and validated all three modes. Mean absolute RGB differences from the unfiltered capture were 12.8240 for Gaussian, 13.9310 for Box, and 13.2821 for Pixelate; the filtered frames were not black. The harness retained only hashes and numeric metrics and deleted every temporary private screenshot. Window capture, representative game capture, and forced GPU-loss recovery remain manual gates.

## Performance results

Measurements use Gaussian radius 12 with two pass pairs. The values are OBS's average frame-render-time metric sampled before and after enabling BlurGo; they are not standalone GPU-profiler timings.

| Runtime | Canvas / FPS | Baseline | Filtered | Delta | Additional skipped frames |

| OBS 31.1.1 SDR | 1280x720 / 30 | 0.1355 ms | 0.1394 ms | +0.0039 ms | 0 |
| OBS 32.2.2 SDR | 2560x1440 / 60 | 0.1197 ms | 0.1413 ms | +0.0216 ms | 0 |
| OBS 32.2.2 SDR | 3840x2160 / 60 | 0.1097 ms | 0.1184 ms | +0.0087 ms | 0 |
| OBS 32.2.2 HDR PQ | 1920x1080 / 60 | 0.1190 ms | 0.1482 ms | +0.0292 ms | 0 |

The dedicated 1920x1080/60 stress run lasted 1,800.125 seconds and performed 6,816 scene switches with 852 memory samples:

- OBS memory: 251.6328 MB first, 204.7695 MB last, 204.7656-251.7539 MB range.
- Linear memory trend: -0.696664 MB/minute; no increasing-memory pattern was observed.
- Render-skipped frames: 8 at the first sample and 9 at the last sample.
- Maximum sampled average frame-render time: 2.0229 ms.
- Total render frames at completion: 127,413.

These figures describe this specific machine and synthetic test pattern; they are not a promise for every scene, GPU, or capture backend.
