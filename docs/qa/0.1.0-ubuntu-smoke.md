The Ubuntu job installed the Debian package produced by the same job, launched a real OBS process under Xvfb, and ran `tools/obs-smoke.py` through OBS WebSocket. Generated test-pattern frames, the OBS log, and `report.json` were retained in the CI artifact; no private display capture was requested.

## Environment

- Ubuntu 24.04.4 LTS on the GitHub-hosted `ubuntu-24.04` runner.
- OBS Studio 32.2.0 and obs-websocket 5.7.4.
- OpenGL 4.5 Core / GLSL 4.50.
- Mesa 25.2.8 llvmpipe (LLVM 20.1.2, 256-bit), forced software rendering for deterministic headless execution.
- 1280x720 at 60 FPS, NV12, Rec. 709, Partial range.

## Functional results

- OBS loaded the packaged `blurgo.so` and logged `[blurgo] loaded successfully (version 0.1.0)`.
- Both bundled effect files compiled on OpenGL without a BlurGo shader error.
- Gaussian, Box, and Pixelate materially changed the source image and preserved a meaningful alpha range.
- Mix 0% and radius 0 produced pixel-identical passthrough output.
- A filter on a nested scene materially changed the complete scene composite.
- Live settings, source resize, filter reorder/removal, 20 scene switches, and disposable-source deletion completed without a BlurGo failure.
- The scene-filter state was readable at the end of the run. Restart persistence is covered by the Windows runtime report, not by this headless Ubuntu run.

## Performance context

OBS reported 17.8504 ms average frame-render time in the unfiltered sample and 21.7449 ms with a radius-12, two-pass Gaussian filter, a delta of 3.8945 ms. CPU usage increased from 43.8740% to 87.9808%, and render-skipped frames increased by 82 during the sampled interval.

These figures measure Mesa llvmpipe software rendering on a shared CI VM. They validate execution and failure handling, not production GPU performance. The representative hardware measurements remain in the [Windows runtime QA report](0.1.0-windows-smoke.md).

## Scope and remaining gates

This run closes native Ubuntu source/nested-scene rendering for the 0.1.0 candidate. It does not cover a physical Linux GPU, Linux display/window/game capture, restart persistence, or forced GPU reinitialization. See [the 0.1.0 gate status](0.1.0-gate-status.md) for the release decision.
